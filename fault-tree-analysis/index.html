故障树分析（FTA）

从顶事件（不希望发生的结果）出发，按 GB/T 4888-2009 / IEC 61025:2006 符号体系自上而下层层分解：矩形=顶/中间事件、圆形=基本事件、菱形=未展开事件、AND 门=平底拱形、OR 门=弧底尖顶形、INHIBIT 门=六边形+椭圆条件事件、三角形=转移符号。内置最小割集（MCS）定性分析与顶事件概率定量计算，支持 PNG / JSON / 文本导出，数据自动保存在本机浏览器 — 适用于事故树建模、隐患排查、安全评估报告与培训

本工具依据的现行版标准（2026-10-25 实证核查）： GB/T 4888-2009 故障树名词术语和符号（2009-10-15 发布 / 2009-12-01 实施，2025-03-27 复审继续有效，代替 GB/T 4888-1985）—— 符号与术语依据 · IEC 61025:2006 Fault tree analysis (FTA)（Ed 2.0，2006-12-13 发布，stability date 2029）—— 建树与定性/定量分析方法依据 · GB/T 7829-1987 故障树分析程序 —— 建树流程参考 · GB/T 37080-2018 / IEC 62502:2010 事件树分析（ETA）—— 与 FTA 衔接的场景后果分析（本站另有 ETA 工具）
两个最容易画错的地方，先看这里： ① 逻辑门方向不能反：故障树是自上而下推理 —— 顶事件在上，导致它的事件在下。「下层所有事件同时发生，上层事件才发生」用 AND 平底拱形门；「下层任一事件发生都足以使上层事件发生」用 OR 弧底尖顶门。把或门画成与门，会凭空漏掉大量单因素失效路径（MCS 阶数算错，整改优先级全错）。 ② 基本事件与未展开事件不能混用：圆形基本事件是「分析的最底层、无需继续展开」；菱形未展开事件是「信息不足或概率极低，本棵子树不再向下展开」—— 菱形不是「不重要」，而是「本图到此为止」，应在文字里注明不再展开的原因。
选中节点属性 类型： 概率： %（留空=不参与定量计算）
怎么加图形：先点选画布里的一个节点 → 点工具栏 ＋ 添加子事件（矩形会展开为 OR 门 + 2 个基本事件，逻辑门会追加 1 个输入事件）；也可直接点节点右上角的 ＋。双击图形改文字 · 节点右上角 ✎ 编辑 / ＋ 展开 · 逻辑门上 ⇄ 切换 AND / OR / INHIBIT · 所有修改自动保存在本机浏览器。
符号速记：矩形=事件（可展开） · 圆形=基本事件（分析底层） · 菱形=未展开事件 · 平底拱形=AND 与门 · 弧底尖顶=OR 或门 · 六边形=INHIBIT 禁门（配椭圆条件事件） · 三角形=转移到其他页/子树

在「故障树编辑器」页签点 计算最小割集，或直接在编辑器增删节点后点此页签查看结果。定性分析输出最小割集（MCS）；当所有基本事件都填写了概率时，额外输出顶事件发生概率与各基本事件的概率重要度。

1. 七类符号（GB/T 4888-2009 / IEC 61025:2006）

符号是故障树的「语法」：事件符号（矩形/圆形/菱形/椭圆）说明「这是什么事件」，逻辑门符号（平底拱形/弧底尖顶/六边形）说明「事件之间的逻辑关系」，转移符号（三角形）解决「一页画不下」。本编辑器严格按此体系绘制，画错形状即画错逻辑。

2. 建树四步（参照 GB/T 7829-1987 程序）
  1. 定顶事件：选「要分析的不希望发生的结果」，一句话、可判定、有边界。如「卸车过程甲醇泄漏并被点燃」。顶事件太大（「装置着火」）会分解不出逻辑门，太小（「2 号阀门微漏」）会失去分析意义。顶事件是矩形，只能有一个。
  2. 逐层向下分解：问「直接导致它的是什么」——先找中间事件（矩形，还能继续分解的系统状态），分解到底就是基本事件（圆形：硬件失效、人为失误）或未展开事件（菱形：信息不足/概率极低，注明不再展开的原因）。
  3. 每层配逻辑门：中间事件与其下层事件之间必须有且只有一个门 —— 全部必须同时发生用 AND 平底拱形；任一发生即足够用 OR 弧底尖顶；「输入故障 + 特定条件同时满足才输出」用 INHIBIT 六边形（条件画成椭圆，如「有氧气时」）。
  4. 转移与整理：子树在别处另有分析时画三角形转移，避免重复；检查「无逻辑门的中间事件」（缺逻辑）、「门直接连门」（缺事件）、「顶事件写成事故本身」三类结构错误，然后计算最小割集。
3. 常见错误纠正
✖ 常见错误画法✔ 规范方法下的纠正
顶事件写成最终事故（「爆炸伤亡」）顶事件是「不希望发生的结果事件」，通常是中间事件（「泄漏」「坠落」）；最终伤亡与损失是顶事件再往上的后果，属于事件树（ETA）分析的范畴
或门画成与门（怕漏就全用与门）门由下层事件的逻辑决定：任一足够即或门，缺一不可即与门。用错门 = MCS 阶数全错，整改优先级全错
中间事件下不画门，直接连一串事件每个中间事件与下层事件之间必须有且只有一个逻辑门；「直接连」等于隐含或门，评审时说不清
门下面直接接另一个门门的输入必须是事件；需要再分解时应插入一个中间事件（矩形）作为「承上启下」
菱形未展开事件当成「不重要，随便写」菱形=本图不再向下展开（信息不足或概率极低），文字里应注明原因；重要但缺数据的，应补数据后改为圆形基本事件
INHIBIT 门不画条件事件禁门必须配椭圆条件事件（如「有氧气时」「票证违规」）；缺了条件，禁门退化为普通与门，失去意义
转移符号乱指，没有对应接收端每个三角形都应配一句「转自/转至某子树」，且该子树确实存在；单向转移不闭环是评审常见扣分项
一棵树想覆盖全厂所有事故一顶事件一棵树；多事件用多棵树，或用蝴蝶结/LOPA/ETA 衔接（本站均有对应工具）

两组示例的分析看点
示例顶事件分析看点
甲醇卸车泄漏燃爆卸车过程甲醇泄漏并被点燃顶事件=「泄漏」与「点火源」同时具备（AND 门）→ 割集全是二阶，说明单改一侧（只防漏或只控火）都不够；动火点燃一支挂 INHIBIT 门+「票证审批不合规」条件，整改抓手是管住票证而非禁止一切动火
吊物坠落伤人吊物从作业高度坠落并击中人员「脱钩/断绳」或门里含一个菱形未展开事件（防脱装置失效，缺数据不再展开），提醒补检；坠落区有人一支挂三角形转移（作业许可与监护另有子树），体现「一页画不下、转移保持图纸整洁」的标准用法

2. 定性 / 定量分析口径
概念本工具口径
割集（Cut Set）一组基本事件：当它们同时发生时，顶事件必然发生
最小割集（MCS）已去掉被其他割集包含的冗余事件后的割集。阶数越低越危险：一阶割集意味着「单个事件失效即导致顶事件」，是最优先整改对象
顶事件概率假设各基本事件相互独立：OR 门 P = 1 − ∏(1 − Pᵢ)；AND / INHIBIT 门 P = ∏Pᵢ。仅当所有叶子基本事件都填写概率时给出，否则只做定性分析
概率重要度把某基本事件概率置 0 后顶事件概率的下降量 ΔP。ΔP 越大，该事件的概率管控越「值钱」——决定整改资源优先投给谁
共因失效本工具假设事件独立；实际系统中多事件共因（同一电源、同一人员、同一班组）会显著低估顶事件概率，评审时应专门讨论
