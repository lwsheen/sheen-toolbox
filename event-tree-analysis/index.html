事件树分析（ETA）

从初因事件出发，按 GB/T 37080-2018 / IEC 62502:2010 对每个关键事件（安全功能）做二分叉：成功继续向右，失败转向下一分支，直至枚举全部后果路径。填入频率后自动计算路径频率、后果汇总与敏感度，支持 PNG / JSON / 文本导出，数据自动保存在本机浏览器 — 适用于事故场景后果推演、保护层充分性论证、应急预案与培训

本工具依据的现行版标准（2026-10-25 实证核查）： GB/T 37080-2018 可信性分析技术 事件树分析（ETA）（2018-12-28 发布并实施，2026-03-18 复审继续有效，等同采用 IEC 62502:2010）—— 方法来源 · IEC 62502:2010 Analysis techniques for dependability — Event tree analysis (ETA)（Ed 1.0，2010-10-27 发布，stability date 2027）· IEC 61025:2006 / GB/T 4888-2009 故障树分析（FTA）—— 关键事件失败概率的求取方法（本站另有 FTA 工具）· GB/T 32857-2025 保护层分析（LOPA）—— 独立保护层频率量化的衔接（本站另有 LOPA 工具）
两个最容易画错的地方，先看这里： ① 初因事件只能是「一个」：事件树从一个明确的初因事件出发向右展开。想分析多个初因（「泄漏」和「超压」都要），就画两棵树 —— 混在一棵树里会让路径频率失去意义。 ② 关键事件必须按「时间/因果顺序」排列：列的顺序就是事故演化的顺序（先报警、后联锁、再泄放）。顺序颠倒会让「失败分支」的走向违背物理过程，后果分组全错。每个关键事件还应能回答「谁在监盘、成功率依据什么数据」。

在「事件树编辑器」页签点 计算路径频率 查看结果：路径频率 = 初因频率 × 各关键事件分支概率之积；后果汇总把导向同一后果的路径合并；敏感度给出「哪个安全功能的可靠性最值得投入」。未填频率时仅做定性路径枚举。

1. 事件树五步（参照 GB/T 37080-2018 / IEC 62502:2010）
  1. 确定初因事件：选一个明确的、需要评估其后果的事件（「反应釜超压」「物料泄漏」），并确定其频率（次/年）。初因可以来自 HAZOP 偏差、事故案例或 FTA 顶事件。一棵树只分析一个初因。
  2. 识别关键事件（安全功能）：沿事故演化时间轴问「接下来什么会拦住它」——检测报警、人员响应、联锁切断、泄压、防腐、应急收容……每个功能作为一列，按时间顺序排列。
  3. 二分叉展开：对每个关键事件问「它成功还是失败」：成功路径继续向右，失败路径转向下一个分支。N 个关键事件 → 2^N 条路径，全部枚举、不跳步。
  4. 标后果：每条路径终点写后果（伤害、损失、环境影响），并按严重度分级。多条路径可导向同一后果，汇总时合并。
  5. 定量计算：路径频率 = 初因频率 × 路径上各分支概率之积（事件独立假设）。后果频率 = 各路径频率之和。关键事件的失败概率可由故障树（FTA）求取（本站另有 FTA 工具）——这是 IEC 62502 与 IEC 61025 的标准衔接点。

3. 常见错误纠正
✖ 常见错误画法✔ 规范方法下的纠正
一棵树塞进多个初因事件一棵树一个初因；多初因分别建树，各自输出后果频率
关键事件不按时间顺序排列（把联锁放在报警前面）列序 = 事故演化时序；顺序错了，失败分支的物理意义就错了
「成功/失败」概率之和不等于 1每个关键事件是完备二分叉：P(成功) = 1 − P(失败)。本工具按此自动互补
只画「全失败」一条路径就下结论2^N 条路径必须全部枚举；后果汇总要按后果合并路径，漏路径会低估风险
后果写成「事故」而不写伤害对象后果应写可评估的对象：人员伤亡程度、物料损失量、环境影响范围、停产时间
把关键事件的失败概率拍脑袋填 0.5失败概率应有数据依据（部件失效率、历史统计、FTA 计算）；无数据时至少给区间并做敏感度分析
忽略共因失效（同一电源带两个「独立」联锁）本工具假设事件独立；共因会显著低估后果频率，评审时应专门讨论
