两个最容易画错的地方，先看这里： ① 预防屏障与减缓屏障不能混放：预防屏障在顶上事件左侧，作用是阻止顶上事件发生（如作业前气体检测）；减缓屏障在右侧，作用是顶上事件已经发生后减轻后果（如灭火系统、应急预案）。把「应急器材」画到左边是最常见的错误。 ② 屏障必须可验证：写「加强管理」「提高意识」不算屏障 —— 每一条屏障都应能回答「谁在做、多久做一次、怎么做记录、失效了什么现象」，并在图上把失效的屏障标为失效。

1. 什么是蝴蝶结模型

蝴蝶结（Bowtie）模型把一次「顶上事件」（Top Event，风险从「尚未失控」滑向「已经失控」的那个转折点，如「甲醇泄漏」「人员高处坠落」）放在中间： 向左追是什么原因可能导致它（威胁）和靠什么拦住它（预防屏障）； 向右追是发生后最坏怎样（后果）和靠什么把伤害压到最小（减缓/恢复屏障）。 整张图形似领结，故名蝴蝶结。它是 GB/T 27921-2023《风险管理 风险评估技术》收录的风险评估技术之一，最大价值是一张图把「事前防」和「事后救」同时讲清楚，适合跨部门沟通与培训。

2. 五列含义与常见画错
要素画什么常见画错 / 纠正
威胁（左列·黄）可能直接引发顶上事件的原因、失效模式或触发条件写「管理不到位」这类泛泛原因 → 应写成可观察的具体场景，如「鹤管接口未试漏即卸车」
预防屏障（左二·蓝）位于威胁与顶上事件之间、阻止顶上事件发生的硬件/软件/管理措施把应急救援措施画到左边 → 应急属于减缓屏障；预防屏障必须「挡在事件前」
顶上事件（中心·深灰）分析对象的转折点事件，一句话、可判定写成事故本身（「爆炸死人」）或写成原因（「违章作业」）→ 顶上事件应是「泄漏」「坠落」这类中间事件
减缓/恢复屏障（右二·橙）顶上事件发生后减轻后果或帮助恢复的措施只画灭火器不画「报警—疏散—救援—恢复」整条链 → 减缓屏障通常多层，应逐层列出
后果（右列·红）该威胁路径下最坏会导致的伤害、损失、环境影响只写「事故」不写伤害对象 → 后果应写「人员中毒/火灾爆炸/水体污染」等可评估对象
3. 四步画法
  1. 定顶上事件：用一句「主语 + 动作 + 判据」描述，如「受限空间内可燃气浓度达到爆炸下限」。顶上事件选得太大（「装置着火」）会画不出屏障，选得太小（「1 号阀门微漏」）会失去分析意义。
  2. 向左列威胁 → 配预防屏障：先穷举威胁（建议从人的行为、物的状态、环境条件、管理接口四类头脑风暴），再为每条威胁配预防屏障；一条威胁可配多条屏障，多层屏障才是「保护层」思路。
  3. 向右列后果 → 配减缓屏障：按最严重到可接受排列后果；每条后果下配减缓/恢复屏障（检测报警、联锁切断、应急设施、预案、救援、恢复）。
  4. 标失效、排优先级：逐条核对屏障当前是否真实有效（有检测记录吗？联锁投用了吗？），失效的标为「失效」；失效屏障集中的那条路径，就是接下来整改与管控的优先项。
4. 屏障状态怎么标
点屏障条底部的 ✓ / ✕ 可在两种状态间切换：✓ 有效（蓝/橙底实线框）= 该屏障当前真实投用且可验证；✕ 失效（红虚线框）= 缺失、超期未检、被旁路或形同虚设。一张「全是 ✓」的蝴蝶结图没有分析价值——失效标注才是蝴蝶结图用于隐患排查与审核的看点：失效屏障即整改项。
5. 适用与局限
蝴蝶结是「单场景」定性工具：一张图只覆盖一个顶上事件。系统性偏差排查用 HAZOP、保护层与频率量化用 LOPA（本站另有 LOPA 工具）、全要素风险梳理用 GB/T 24353-2022 风险管理流程。蝴蝶结图不输出风险等级数值，不能替代定量风险评价；图上屏障的充分性最终须经评审确认。屏障是否「独立有效」（是否共用同一失效原因）是进阶判读点，建议在评审时逐条讨论。

3. 常见错误纠正
✖ 常见错误说法 / 画法✔ 规范方法下的纠正
蝴蝶结是「鱼骨图加箭头」，想到哪画到哪它是成方法的风险评估技术（GB/T 27921-2023 收录）：以顶上事件为唯一中心，两侧各按「威胁/后果 → 屏障」结构化展开
预防屏障里写「加强管理」「提高意识」屏障须可验证：写明对象、措施、频次与记录；无法验证的口号不是屏障
把应急救援、灭火器材画在左边当预防屏障应急与救援在顶上事件右侧，属减缓/恢复屏障；左边只放「阻止事件发生」的措施
整张图全是「有效」屏障，没有失效标注失效标注是蝴蝶结图的核心输出：逐条核对屏障现状，失效项即整改清单
顶上事件写成最终事故（「爆炸伤亡」）顶上事件是转折点（「泄漏」「坠落」），最终伤亡放右列后果；写成事故会让右侧无屏障可画
一张图想把全厂所有风险讲完蝴蝶结是单场景工具：一个顶上事件一张图；多事件用多张图，或用 HAZOP/LOPA 衔接
